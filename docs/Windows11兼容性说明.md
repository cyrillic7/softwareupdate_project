# Windows 11 兼容性说明

## WSASendCB 错误问题

### 问题描述
在 Windows 11 系统上使用测试连接功能时，可能出现以下错误：
```
[错误信息] WSASendCB - ERROR: broken assumption, io:00000171DF632180, sent:33, remaining:0
```

### 问题原因
这是 Windows 11 系统下 paramiko 库的已知兼容性问题，主要原因包括：

1. **Windows Socket API 变化**: Windows 11 对底层网络 API 进行了优化，导致某些第三方库的兼容性问题
2. **内存管理差异**: paramiko 库在 Windows 11 下的内存管理模式可能出现问题
3. **网络堆栈更新**: Windows 11 的网络堆栈变化可能影响 SSH 连接的建立

### 解决方案

#### 自动修复（已实现）
软件已经更新了测试连接脚本，增加了以下兼容性处理：

1. **自动重试机制**: 检测到 WSA 错误时自动重试连接
2. **超时时间调整**: 为 Windows 11 增加了更长的超时时间
3. **Socket 选项优化**: 使用更保守的 Socket 设置
4. **延迟处理**: 在连接建立过程中增加适当的延迟

#### 手动解决方案

##### 方案1: 重启应用
```bash
# 完全关闭软件后重新启动
# 这可以清理可能存在的 Socket 状态问题
```

##### 方案2: 使用系统 SSH 客户端
- 如果测试连接仍然失败，可以暂时跳过测试连接功能
- 直接使用上传和升级功能，软件会使用系统的 SSH 客户端

##### 方案3: 网络设置检查
1. **检查防火墙设置**:
   - 临时禁用 Windows Defender 防火墙进行测试
   - 如果成功，将软件添加到防火墙例外

2. **检查网络适配器**:
   - 更新网络适配器驱动程序
   - 重置网络适配器设置

##### 方案4: 更新 Python 依赖
如果您在命令行中使用：
```bash
pip install --upgrade paramiko cryptography
```

### 预防措施

1. **定期重启软件**: 长时间使用后建议重启软件
2. **避免并发连接**: 不要同时进行多个连接测试
3. **网络环境稳定**: 确保网络环境稳定，避免频繁切换网络

### 错误日志分析

如果仍然遇到问题，请查看详细的错误信息：

- **WSASendCB 错误**: 通常是 Windows Socket 兼容性问题
- **timeout 错误**: 可能是网络连接问题
- **connection refused**: 目标服务器连接被拒绝

软件现在包含以下技术改进：
